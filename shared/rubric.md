# Survey Score rubric (`bs-skills-1.0`)

The judge's question sheet. Every item a judging LLM answers when it scores a survey, with the words the report says back. Ported from BlockSurvey's in-product Survey Score (rubric 1.2, `rubric.py`) and the conversion-focused v2 proposal.

**Counts:** survey-level 29 shipped (27 scored + 2 companions `C5_gap_topic`, `K_survey_kind`) + 12 v2 (A8, A9, A10, B7, B8, C7, E7, E8, E9, F3a, F3b, F5) + 1 v2 companion `X2_audience_kind` = 42; per-question 15 shipped (Q1–Q14 with Q3a/Q3b) + 11 v2 (Q15–Q25) + 7 locators + 1 overview locator + `R_role` = 35. **Total rows: 77.**

The LLM answers the items. `scripts/survey_score_calc.py` does the arithmetic (see [scoring.md](scoring.md)). Static checks (counting, thresholds, structure) are in [static-checks.md](static-checks.md). Do not count or calculate inside a judgment; just answer the item as written.

## How to read this file

| Column | Meaning |
| --- | --- |
| `id` | Stable item id. Category letter + number + slug. Never renumbered. |
| `scope` | `survey`: judged once on the whole survey. `question`: judged once for every question it applies to. |
| `primitive` | `score`: pick one level (0 = worst). `noul`: give `p`, the probability the statement is **true**. `choice`: pick one key. |
| `applies` | Which questions a per-question item is judged on (see [Applicability](#applicability)). |
| `kinds` | Survey kinds (from `K_survey_kind`) the item is judged for. `all` = every kind. |
| `weight` | Weight inside its category. 0 = informational. |
| `flags` | `good_when_yes` (for a Noul, yes is good, so `p` near 0 is the problem); `informational` (never a finding on its own); `target` (where the fix happens: `title`, `welcome`, `thank_you`, `question`, `questions`, `survey`); `locates` (for a locator: the survey item it points at); gates and notes. |
| `instructions` | What the judge is asked, verbatim. Backticked paths point at fields of the survey (see [Context paths](#context-paths)). |
| `criteria` | Score: levels worst→best (`0 …<br>1 …`). Noul: what `true` and `false` look like (`—` when the instruction says it all). Choice: the keys. |
| `severity` | Severity of the finding at that level (Score), when the Noul is a problem, or for that choice. Levels not listed never produce a finding. |
| `roast` | What the report says. Specific, honest, a little funny, never cruel. |
| `fix` | One concrete action. Lines starting role `information` / role `consent` replace the fix for questions with that role. |
| `funnel` | Funnel stage the item feeds: `start`, `continue`, `finish`, `answer_quality`, `actionability` (`—` for classifiers). |
| `source` | `shipped-1.2`: verbatim from the shipped rubric. `v2`: from the v2 proposal tables. |

### Conventions

- **Score** levels are ordered worst → best; index 0 is worst. The value is `level / (levels − 1)`.
- **Noul** items are phrased so that **yes = problem**, unless flagged `good_when_yes`. The value is `1 − p` (or `p` when `good_when_yes`).
- **Choice** items pick exactly one key from `criteria`. Most are informational; `Q19_recall_period` and `Q25_best_type` carry weight (see scoring.md).
- **Placeholders** in roast and fix: `{ref}` (question ref, e.g. `Q4`), `{label}` (question label, first 80 characters), `{title}` (survey title). The v2 rows add `{stated_minutes}` (`settings.stated_minutes`, or "a few" when unset), `{type}` (current `question.type`) and `{choice}` (the type picked by `Q25_best_type`).
- Marks inside cells: *(authored)* = the v2 proposal gives no text, so it was written for this port in the same voice; *(generalised, see note 1)* = the v2 proposal gives an example about one specific question, re-written with placeholders; *(from shipped F3)* = reused from the shipped `F3_incentive_clear`.
- A finding at a Noul `p` between 0.7 and 0.85 (or 0.3 and 0.15 for `good_when_yes`) is reported one severity lower and flagged *uncertain*; a Score answer with confidence below 0.6 likewise; below 0.35 it is only an `info` note. Full rules in scoring.md.

### Context paths

The instructions keep the backticked paths of the shipped rubric. Read them against the [portable survey JSON](survey-format.md) like this:

| Path in an instruction | Where to look in the portable survey |
| --- | --- |
| `title`, `description`, `welcome`, `thank_you`, `questions` | The top-level fields of the same name. |
| `welcome.description` (shipped text said `welcome[].description`) | `welcome.description`. The portable survey has one welcome screen. |
| `stats.answerable_questions` | Number of questions whose `type` is not `statement` or `group` (`survey_lint.py` prints it in `stats`). |
| `survey.title` / `survey.purpose` | `title` / `purpose` + `description` + `welcome.description` (the first ~600 characters). |
| `question` | The question being judged. `question.label`, `.description`, `.options`, `.rows`, `.columns`, `.required`, `.has_other`, `.has_none`, `.has_prefer_not_to_answer`, `.role`, `.type` are its fields. |
| `previous_question`, `question.previous_question` | The entry immediately before it in `questions`. |
| `parent_group` | The `group` question named by `question.group`. |
| `reached_from` | The questions whose `jumps[].to` is this question's `ref`, with their `when`. |
| `scales` (`B8`) | Every `rating`, `nps`, `likert`, `slider` and `matrix` question, and every `single_choice` whose options form an ordered scale, in survey order, with their options / columns / `scale.labels`. |
| `question.type` in `Q9_type_fit` | Q9's instructions name BlockSurvey types. Read them as: `multiplechoice` = `single_choice` / `yes_no`; `checkboxes` = `multi_choice`; `dropdown` = `dropdown`; `singletextbox` = `short_text`; `commentbox` = `long_text`; `number` = `number`; `matrixrating` = `matrix` (or `likert` with rows); `rating` / `numberrating` / `slider` = `rating`, `likert`, `nps`, `slider`; `ranking`, `date`, `email` as named; `fileupload` = `file`. Full map in [question-types.md](question-types.md). |

### Applicability

Per-question items are judged only where they apply (ported from `rubric.py::item_applies`; full rules in scoring.md):

- **Not answerable** (`statement`, `group`): only `Q1_clarity`, `Q2_double_barreled`, `Q3a_leading`, `Q3b_presuming`, `Q13_grammar`.
- **`role` is `information` or `consent`**: only `Q1_clarity`, `Q4_jargon`, `Q5_relevance`, `Q13_grammar`, `L_hard_to_read`, `L_pressuring`.
- **`shown_when` is set**: skip `Q3b_presuming`; skip `Q5_relevance` when the condition names an earlier question.
- **`applies`**: `all` = every remaining question; `options` = has `options` or `columns`; `with_options_or_columns` = same; `single_choice` = has options and type is `single_choice`, `dropdown`, `yes_no` or `consent`; `scale` = a scale type (`rating`, `nps`, `likert`, `slider`, `matrix`) or a `single_choice`/`dropdown` with 3+ options, and has options or columns; `text` = `short_text` or `long_text`; `quantity` (v2) = `number`, `slider`, `date`, or a `short_text` whose label asks for an amount.
- **`kinds`**: when `K_survey_kind` is known with confidence ≥ 0.5 and is not in the item's list, the item is skipped (not a defect for that kind).

### G. Conversion (v2 composite)

G has no items of its own. It re-uses existing evidence to answer "will people finish this?" (v2 §7.1): `A8_respondent_benefit`, `A9_sponsor_named`, `E7_welcome_scannable`, `E8_straightlining_risk`, `B7_end_loading` and the mean of `Q15_abandon_risk` across questions (each at its rubric weight), minus the deductions of the static checks `S50_welcome_too_long`, `S51_early_friction`, `S30_matrix_too_large`–`S34_open_ended_overload` and `S46_first_question_open_text`–`S48_pii_before_content`. Its weight comes from the weight profile in scoring.md (0 for the default profile). Counting these items twice is deliberate: conversion matters more than completeness for customer-facing surveys.

## Supersession and pairing

- `F3_incentive_clear` (shipped) asks a conditional question ("answer yes if no incentive is mentioned"). v2 splits it into `F3a_incentive_mentioned` (evidence only) and `F3b_incentive_delivery_clear`. When both F3a and F3b are judged, F3 is ignored. Judges should answer F3a and F3b; F3 stays so older judgments still score.
- `Q9_type_fit` says *whether* the type fits; `Q25_best_type` says *which* type fits. Keep both. When Q25 names a type different from the current one with confidence ≥ 0.6, its fix ("Change {ref} to a {choice} question.") replaces Q9's fix on that question.
- `Q3a_leading` and `Q3b_presuming` are the two halves of the old `Q3_leading` (rubric 1.1). The v2 table re-states them; the shipped wording above is the one in use.
- `E7_welcome_scannable` pairs with the static word count `S50_welcome_too_long`; `E8_straightlining_risk` with `S27_monotony_run` and `S31_consecutive_matrices`; `B5_redundant_questions` with `S10_duplicate_labels`.
- The v2 proposal names the survey-kind classifier `X1_survey_kind` with ten kinds. This port keeps the shipped `K_survey_kind` (six kinds) and derives the v2 weight profile from `K_survey_kind` + `X2_audience_kind` (mapping in scoring.md), so there is no X1 row.
